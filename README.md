# Q.sight — 마음을 남기는 서명

> 기부·봉사·유산기부의 선한 의지를 **AI 대화로 정리하고, 전자서명으로 남기는** 플랫폼
> AI Builder Sprint 2026 출품작 (모두싸인 특별 주제)

기부 약정은 지금도 대부분 종이와 전화로 이루어집니다. 기관은 서식을 만들어 보내고,
기부자는 항목을 이해하지 못한 채 서명합니다. Q.sight는 그 과정을 **기관용 웹**과
**기부자용 웹**으로 나누고, 두 웹을 API로만 잇습니다.

## 1. 무엇을 만들었나

| | 기관용 웹 | 기부자용 웹 |
| --- | --- | --- |
| 쓰는 사람 | 모금 담당자 | 기부자 |
| 하는 일 | 사업 등록, 계약서 서식 등록, 약정·이행 관리 | 상담·약정·서명·보관 |
| 화면 | 12개 | 24개 |

두 웹은 **API로만 연결**됩니다. 기관이 계약서 서식을 바꾸면 기부자용 챗봇의 질문이
저절로 따라 바뀝니다. 질문 목록이 코드에 없기 때문입니다.

**핵심 차별점은 유산기부 녹음유언입니다.** 전자서명으로 하는 것은 '기부 의사 등록'까지이고,
유언은 민법 제1067조가 정한 녹음 방식으로 본인이 직접 말하게 돕습니다.
법을 우회하지 않고 법에 맞춘 설계입니다.

## 2. 5분 안에 보실 것 (권장 순서)

서버를 띄우는 방법은 [3장](#3-로컬-기동-실행-가이드)에 있습니다.
**API 키가 없어도 아래 대부분이 동작합니다.**

### ① 기관이 서식을 바꾸면 챗봇 질문이 바뀐다 — http://localhost:8080/corporate/

1. 왼쪽 메뉴 `모금 사업`으로 들어갑니다. 계약서 서식은 이 메뉴 안에서 전환해 편집합니다
2. 서식의 입력 항목을 하나 추가하거나 지우고 저장합니다
3. 기부자용 웹(http://localhost:5173)에서 그 사업으로 상담을 시작합니다
4. 방금 바꾼 항목이 챗봇 질문에 그대로 반영됩니다

> 화면에 질문이 하드코딩돼 있지 않다는 것을 가장 빠르게 확인하실 수 있는 경로입니다.

### ② 대화로 약정 항목을 모은다 — http://localhost:5173

`새로운 약속 시작하기` → 사업 선택 → 상담 시작. 한 문장에 여러 항목을 섞어 말해보세요.

```
"김민준이고 010-1234-5678이에요. 매달 3만원씩 1년간 낼게요."
→ 이름·연락처·금액·주기·기간을 한 번에 인식
```

애매하게 말하면 **지어내지 않고 되묻습니다.**

```
"매달 3만원씩 내년까지 낼게요"
→ "내년까지"라고 하셨는데, 정확히 어떻게 기록할지 몰라서요. 약정 기간을 알려주시겠어요?
```

금액·주기는 받아들이고 애매한 기간만 골라 되묻습니다.

### ③ 확인 → 서명 요청

수집이 끝나면 확인 화면에서 내용을 정리해 보여주고, 서명자 이메일을 따로 받은 뒤
전자서명을 요청합니다. **모두싸인 키가 없으면 데모 모드로 동작해 실제 메일은 나가지 않습니다.**

### ④ 유산기부 — 녹음유언 (핵심 차별점)

`새로운 약속 시작하기` → `유산 기부`

안내·동의 → 사업 선택 → 상담 → 대본 확인 → 의향 등록 → 증인 등록 → 녹음 → 자가 확인 → 완료.

보실 점:

- **대본을 AI가 쓰지 않습니다.** 코드가 정해진 템플릿에 값을 끼워 넣습니다
- 법정 요건 5종이 대본에 다 없으면 **서버가 아예 뜨지 않습니다**
- 파일 업로드·일시정지 버튼이 없습니다 (편집본·중단 녹음은 무효 사유)
- 고지문과 필수 동의에 **음성 안내(🔊)** 가 붙어 있습니다. 이용자 상당수가 고령이기 때문입니다.
  대본에는 붙이지 않았고, **녹음 중에는 잠깁니다** — 합성음이 마이크에 섞이면 안 되기 때문입니다

## 3. 로컬 기동 실행 가이드

기부자용 웹과 기관용 웹이 서로 통신하는 구조라 **서버 3개**를 순서대로 띄웁니다.

```
브라우저 :5173 ──/api──▶ 기부자용 서버 :4000 ──▶ 기관용 서버 :8080 ──▶ 모두싸인
                              │
                              └──▶ Upstage Solar (AI 챗봇)
```

저장소는 두 웹으로 나뉩니다.

```text
qsight_corp/      기관용 — 모금 담당자가 쓰는 쪽
  backend/          FastAPI 서버 (기관용 화면도 여기서 서빙)  :8080
  frontend/         기관용 화면 (W1~W10)
qsight_client/    기부자용 — 기부자가 쓰는 쪽
  server/           Node 서버 (AI 챗봇, 기관 API 중계)        :4000
  client/           React 화면                                :5173
```

### 3-1. 기관용 서버 (먼저 실행)

```bash
pip install -r qsight_corp/backend/requirements.txt
python -m uvicorn server.main:app --port 8080 --app-dir qsight_corp/backend --reload
```

- 기관용 웹 — http://localhost:8080/corporate/
- API 문서 — http://localhost:8080/docs

첫 실행이면 모금 사업과 계약서 서식이 **자동으로 채워집니다**. 별도 준비가 필요 없습니다.

### 3-2. 기부자용 서버

```bash
cd qsight_client/server
cp .env.example .env
npm install
npm run dev
```

### 3-3. 기부자용 화면

```bash
cd qsight_client/client
npm install
npm run dev
```

http://localhost:5173 으로 접속합니다.

### 3-4. 잘 떴는지 확인

```bash
curl http://localhost:8080/api/health
curl http://localhost:4000/api/health
```

각 폴더의 README에 더 자세한 설명이 있습니다 —
[기관용](qsight_corp/backend/README.md) · [기부자용](qsight_client/README.md).

## 4. 실행 환경 정보

| | 필요 버전 | 개발·검증 환경 |
| --- | --- | --- |
| Node.js | 18 이상 (`--env-file`, `MediaRecorder` 사용) | v24.15.0 |
| npm | 9 이상 | 11.12.1 |
| Python | 3.10 이상 (`X \| None` 타입 표기 사용) | 3.14.3 |
| OS | 무관 | Windows 11 |
| 브라우저 | **크롬 또는 엣지 권장** | 유산기부 녹음이 `MediaRecorder`를 씁니다 |

- **데이터베이스·클라우드 서비스가 필요 없습니다.** 데이터는 각 서버의 `data/` 폴더에
  JSON 파일로 저장되며 첫 실행 시 자동으로 만들어집니다
- 배포하지 않은 상태이며, 위 로컬 실행 가이드로 재현하실 수 있습니다
- 배포하는 경우 **HTTPS가 필요합니다.** 유산기부 녹음(`getUserMedia`)이 보안 컨텍스트에서만
  동작하기 때문입니다 (`localhost`는 예외)

## 5. 환경변수 정보

**키가 하나도 없어도 대부분의 기능이 동작합니다.** 모두싸인 자격증명이 없으면 기관용 서버가
자동으로 데모 모드로 전환되어, 실제 메일 발송 없이 약정 생성과 서명 상태 조회가 끝까지 진행됩니다.

`.env` 파일은 저장소에 포함되지 않습니다. 각 폴더의 `.env.example`을 `.env`로 복사한 뒤
전달받은 값을 채워 넣으면 됩니다.

### 기관용 — `qsight_corp/backend/.env`

| 키 | 설명 | 없으면 |
| --- | --- | --- |
| `MODUSIGN_EMAIL`·`MODUSIGN_API_KEY` | 모두싸인 **기관 계정**. 문서 생성·서명 요청 발송 | 데모 모드 (실제 메일 미발송) |
| `UPSTAGE_API_KEY` | 서식 PDF·영수증 파싱 (Document Parse / Information Extract) | 스캔본 항목 추출 불가 |
| `ORG_NAME`·`ORG_MANAGER` | 계약서에 찍히는 기관명·담당자 | 기본값 사용 |
| `MODUSIGN_FORCE_MOCK` | `1`이면 키가 있어도 데모 데이터 사용 | `0` |
| `PORT` | 기관용 서버 포트 | 8080 |

### 기부자용 — `qsight_client/server/.env`

| 키 | 설명 | 없으면 |
| --- | --- | --- |
| `UPSTAGE_API_KEY` | 챗봇 값 추출 (Solar Pro 2) | **AI 상담만 불가** (그 외 정상) |
| `UPSTAGE_MODEL` | 모델명 | `solar-pro2` |
| `QSIGHT_CORP_API` | 기관용 서버 주소 | `http://localhost:8080` |
| `MODUSIGN_EMAIL`·`MODUSIGN_API_KEY` | 모두싸인 **개인 계정** (증서함 조회 전용) | 증서함 목록만 비활성화 |
| `PORT` | 기부자용 서버 포트 | 4000 |

> ⚠️ 기부자용에 넣는 모두싸인 키는 기관용과 **다른 개인 계정**이어야 합니다.
> 기부자용 웹은 문서를 만들거나 서명을 요청하지 않고, 본인이 서명한 문서를 조회만 합니다.

### 키 없이 확인 가능한 범위

**됩니다** — 사업 목록, 계약서 서식 편집, 확인 화면, 약정 생성(데모 모드), 서명 상태 조회,
유산기부의 대본 생성·증인 등록·완료 화면까지.

**추가 조건이 필요합니다**

| 기능 | 필요한 것 | 없을 때 |
| --- | --- | --- |
| AI 챗봇 상담 | `UPSTAGE_API_KEY` | 대화로 항목을 모을 수 없습니다 |
| 유산기부 **녹음** | **마이크 + 브라우저 권한 허용** | "마이크를 사용할 수 없어요" 안내 후 대기 |
| 실제 서명 완료 | 모두싸인 실키 + **서명자 메일함** | 데모 모드에서 상태가 `서명 진행중`에 머뭅니다 |

녹음은 브라우저가 마이크를 잡아야 해서 자동화된 환경에서는 재현이 어렵습니다.
그 구간은 데모 영상으로 확인해 주세요.

## 8. AI 활용

### Upstage 3종을 모두 사용합니다

| 제품 | 쓰는 곳 | 용도 |
| --- | --- | --- |
| **Solar Pro 2** | 기부자용 서버 | 대화에서 약정 항목 값 추출 (tool calling) |
| **Document Parse** | 기관용 서버 | 계약서 서식 PDF·영수증 이미지에서 텍스트 추출 |
| **Information Extract** | 기관용 서버 | 추출한 텍스트에서 입력 항목·금액·납부일 구조화 |

### AI에 맡긴 것과 맡기지 않은 것

이 프로젝트에서 가장 신경 쓴 부분입니다. **AI는 "사람 말에서 값을 뽑는 일"에만 씁니다.**

| 일 | 담당 |
| --- | --- |
| 사용자 말에서 값 추출 | **AI** (Solar Pro 2, tool calling, temperature 0) |
| 무엇이 아직 안 채워졌는지 판단 | 코드 (스키마와 값의 차집합) |
| 사용자에게 보여줄 문장 | 코드 (스키마의 label·type·options로 조립) |
| 유언 대본 문장 | 코드 (템플릿 + 값) |

챗봇이 보내는 문장을 AI가 쓰지 않기 때문에, **스키마에 없는 질문이나 지어낸 설명이
화면에 나갈 수 없습니다.** (개발 중 "2007년생"을 미성년으로 판단해 보호자 연락처를
요구하거나, 법적 근거를 지어내 설명하는 문제가 실제로 있었고 이 구조로 해결했습니다.)

숫자 항목은 한 겹 더 막습니다. 추출한 값의 **근거가 된 표현에 수(數) 표현이 없으면 버립니다.**

## 9. 실제로 돌아가는 범위 (과장 없이)

**확인된 것**

- 기관용 서식 변경 → 기부자용 챗봇 질문 반영
- 대화 수집 → 확인 → 약정 생성 → 서명 상태 조회
- 애매한 표현 되묻기 (6종 확인: 내년까지 / 당분간 / 좀 많이 / 가끔씩 / 분기마다 / 무관한 말)
- 서식이 대화 중에 바뀌면 메일 발송 전에 감지해 바뀐 항목만 재질문
- 모금이 종료된 사업은 목록·서식·챗봇·약정 생성 네 지점에서 차단
- 유산기부 전 과정 (대본 조립·증인 결격 차단·해시 저장·자가 확인·기관 통보)
- **갓 클론한 저장소를 키 0개, 빈 데이터로 띄워** 위 흐름이 동작함을 확인

**한계로 남은 것**

- **법률 검토가 끝나지 않았습니다.** `legacy-spec.json`의 `reviewed_by`가 `미검토`입니다.
  화면도 "이 등록만으로는 유언이 되지 않는다"고 명시하며, 유효한 유언이 완성됐다고
  말하지 않습니다. 문안은 JSON 한 파일에 모아두어 검토 결과가 나오면 코드 수정 없이 교체됩니다
- 로그인이 없습니다. 기본정보와 유산기부 등록 id를 브라우저가 들고 있어, 기기를 바꾸면
  이전 기록을 찾지 못합니다
- 고향사랑기부·문화유산 후원 화면은 접수 준비 중입니다 (지자체·후원처 데이터 미연동)
- 모두싸인 웹훅은 공인 URL이 필요해 로컬에서 동작하지 않습니다. 수신 로직은 구현되어 있고
  지금은 10초 폴링으로 대체합니다
- 자동화된 테스트 프레임워크가 없습니다. 검증은 [AI_활용_증빙.md 4장](AI_활용_증빙.md)에
  재현 가능한 명령으로 정리했습니다
